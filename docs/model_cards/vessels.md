# Buques: detectores y atributos

Los detectores públicos por sensor generan propuestas provisionales. Un score de 0.90 no acredita precisión de 90%. Las métricas locales definitivas y el alcance validado permanecen pendientes de una muestra humana independiente y congelada.

Los atributos usan un encoder público congelado y cabezas propias por sensor: FPN de 128 canales para S2 y 256 para S1, pooling sobre la región detectada y una cabeza compartida con clasificación y regresión. El tamaño del recuadro se usa para seleccionar características, nunca como eslora o manga. El extractor actual requiere recortes de hasta 512 píxeles. La taxonomía es carga, tanquero, pasajeros, remolcador, pesquero y otros; fuera del alcance el resultado es nulo.

Las recetas `config/models/attributes-s1.yaml` y `attributes-s2.yaml` están sin entrenar. No incluyen pesos propios fingidos ni métricas locales. La prueba automatizada entrena una cabeza pequeña sobre datos de prueba para verificar el guardado, los hashes y el enmascarado; no es un modelo entregable para los puertos.

`cache_reviewed_features` obtiene características del encoder fijado por hash. Cada muestra del dataset contiene etiquetas GeoJSON revisadas y una caché NPZ (`features`, `ids`) con checksum, hash del encoder, nivel de FPN y pooling. `train_attribute_dataset` solo acepta el conjunto de entrenamiento y etiquetas con referencia documentada por campo. Los datos de calibración y prueba se rechazan; sus manifiestos pueden pasarse como conjuntos reservados para comprobar grupos relacionados. Las etiquetas ausentes no contribuyen a la pérdida.

Cada versión entrenada conserva pesos anteriores en otro directorio, SHA256 de pesos/dataset/código/receta, procedencia del encoder, soporte por campo y parámetros de entrenamiento. Nace experimental. Para publicar un campo hay que registrar validación, soporte suficiente, umbral calibrado de familia o error y rango de dimensiones. La falta de un atributo no elimina la detección.

`estimate_attributes` expone las estimaciones crudas de la cabeza entrenada, incluso antes de validar su publicación; `predict_attributes` les aplica la política por campo. `evaluate_attributes` evalúa el conjunto de prueba sobre objetos de referencia revisados, separando el desempeño de atributos de la detección. Solo usa etiquetas con procedencia independiente por campo y comprueba solapamiento de observaciones/grupos con entrenamiento. Reporta resultados crudos y con un umbral fijo externo, sin escoger umbrales a partir de la prueba ni conceder autorización de publicación. La mediana de referencia para dimensiones se calcula exclusivamente con etiquetas válidas del entrenamiento y queda guardada en el manifiesto.

La evaluación incluye precisión, recall, omisiones, falsos positivos por escena e intervalos Wilson al 95%, desglosados por puerto/sensor/zona. Wilson no modela dependencia entre objetos de una escena; una evaluación final debe considerar ese agrupamiento. El gate exige referencia independiente, prueba congelada, checksum de dataset y soporte explícito para cada estrato solicitado. El promedio no oculta un estrato fallido. La clasificación mide abstenciones, matriz de confusión y macro-F1; las dimensiones, MAE, sesgo y cobertura, contra una referencia simple fijada con entrenamiento y comparada sobre el mismo subconjunto.
